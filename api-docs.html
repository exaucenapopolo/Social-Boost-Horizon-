Introduction

Bienvenue dans la documentation officielle de l'API publique Social Boost Horizon. Cette API vous permet de passer des commandes de services de boost de réseaux sociaux (followers, likes, vues, commentaires…) directement depuis votre propre site ou application, sans passer par notre interface web.

Devise

Tous les montants (solde, prix des services, coût des commandes) sont exprimés en XAF (FCFA).

Authentification

Chaque requête doit être accompagnée de votre clé API dans l'en-tête HTTP X-Api-Key.

Fournisseurs intégrés

Le catalogue expose les services de plusieurs fournisseurs partenaires. Le champ provider dans la réponse vous indique l'origine : mtp, afriqueboost ou smmwiz.

Sécurité importante

Votre clé API est un secret. Ne la mettez jamais dans du code JavaScript côté navigateur, ne la publiez pas sur GitHub, ne la partagez avec personne. Les appels à cette API doivent être effectués depuis un serveur (PHP, Node.js, Python, etc.).

Démarrage rapide

En 4 étapes, vous serez opérationnel :

  1. Générez votre clé API Rendez-vous sur votre page de profil, onglet Développeur, puis cliquez sur Générer une clé API. Copiez-la immédiatement : elle ne sera plus jamais réaffichée.
  2. Vérifiez votre solde Appelez GET /api/v1/balance pour confirmer que votre clé fonctionne et connaître votre solde disponible.
  3. Récupérez le catalogue Appelez GET /api/v1/services. Chaque service possède un identifiant unique de la forme provider_id (ex. mtp_1234).
  4. Passez votre première commande Appelez POST /api/v1/order avec le service_id, le lien cible et la quantité souhaitée.

Exemple complet (cURL)

# 1. Vérifier le solde
curl https://socialboosthorizon.com/api/v1/balance \
  -H "X-Api-Key: votre_cle_api"

# 2. Voir le catalogue
curl https://socialboosthorizon.com/api/v1/services \
  -H "X-Api-Key: votre_cle_api"

# 3. Passer une commande
curl -X POST https://socialboosthorizon.com/api/v1/order \
  -H "X-Api-Key: votre_cle_api" \
  -H "Content-Type: application/json" \
  -d '{
    "service_id": "mtp_1234",
    "link": "https://instagram.com/mon_compte",
    "quantity": 1000
  }'

URL de base

Toutes les requêtes doivent être envoyées à l'URL suivante :

https://socialboosthorizon.com

Le chemin complet d'un endpoint est donc, par exemple : https://socialboosthorizon.com/api/v1/balance

Authentification

Chaque requête doit inclure votre clé API dans l'en-tête HTTP X-Api-Key. Sans cet en-tête (ou avec une clé invalide/révoquée), l'API répond 401 et n'effectue aucune action.

En-tête à envoyer

X-Api-Key: votre_cle_api_ici

Où trouver ma clé ?

Connectez-vous à votre compte sur profil.html, onglet Développeur. Si aucune clé n'existe, cliquez sur Générer une clé API. Si vous pensez qu'une clé a été compromise, cliquez sur Révoquer puis générez-en une nouvelle.

Bonnes pratiques

  • Stockez la clé dans une variable d'environnement côté serveur (jamais dans le code source).
  • Utilisez une clé différente par environnement (dev / prod) si possible.
  • En cas de fuite suspectée, révoquez immédiatement et régénérez.

Lister les services

GET /api/v1/services

Retourne le catalogue complet des services disponibles en temps réel auprès de nos fournisseurs partenaires. Chaque service possède un identifiant service_id à réutiliser lors de la commande.

Format du service_id

Le service_id est de la forme <provider>_<idFournisseur> :

  • mtp_1234 → service 1234 chez MoreThanPanel
  • afb_5678 → service 5678 chez AfriqueBoost
  • smmwiz_910 → service 910 chez SMMWiz

Vous devez utiliser cette chaîne exactement telle quelle dans POST /api/v1/order.

Paramètres (query)

ParamètreTypeDescription
catalog optionnel string Filtre par fournisseur (mtp, afriqueboost, smmwiz) ou par catégorie (ex. Instagram, TikTok). Sans ce paramètre, tout le catalogue est renvoyé.

Réponse

200 OK
{
  "success": true,
  "services": [
    {
      "service_id": "mtp_1234",
      "provider": "mtp",
      "name": "Instagram Followers [Real]",
      "category": "Instagram",
      "type": "default",
      "price_per_1000": 5000,
      "min": 100,
      "max": 10000,
      "refill": true,
      "cancel": false,
      "description": "Followers Instagram haute qualité, garantis 30 jours"
    }
  ],
  "total": 248
}

Détail des champs

ChampTypeDescription
service_idstringIdentifiant unique à utiliser pour commander.
providerstringFournisseur d'origine : mtp, afriqueboost ou smmwiz.
namestringNom commercial du service.
categorystringCatégorie (Instagram, TikTok, YouTube…).
typestringType technique du service (default, package…).
price_per_1000integerPrix en XAF pour 1000 unités.
minintegerQuantité minimale commandable.
maxintegerQuantité maximale commandable.
refillbooleantrue si le service supporte le refill automatique.
cancelbooleantrue si la commande peut être annulée.
descriptionstringDescription détaillée (peut être null).
 
# Tout le catalogue
curl -X GET https://socialboosthorizon.com/api/v1/services \
  -H "X-Api-Key: votre_cle_api"

# Filtrer par fournisseur
curl -X GET "https://socialboosthorizon.com/api/v1/services?catalog=mtp" \
  -H "X-Api-Key: votre_cle_api"

# Filtrer par catégorie
curl -X GET "https://socialboosthorizon.com/api/v1/services?catalog=Instagram" \
  -H "X-Api-Key: votre_cle_api"

headers = {"X-Api-Key": "votre_cle_api"}
params = {"catalog": "Instagram"}

response = requests.get(url, headers=headers, params=params)
print(response.json())

    CURLOPT_URL => "https://socialboosthorizon.com/api/v1/services?catalog=Instagram",
    CURLOPT_RETURNTRANSFER => true,

Passer une commande

POST /api/v1/order

Crée une nouvelle commande auprès du fournisseur correspondant au service choisi. Le coût est calculé côté serveur (vous ne pouvez jamais imposer un prix) et votre solde est débité de manière atomique.

Règles de sécurité

  • Le service_id doit correspondre à un service réellement présent dans le catalogue actuel.
  • La quantity doit respecter les bornes min et max du service.
  • Le solde doit être suffisant. Sinon, la commande est refusée avant tout appel au fournisseur.
  • Toute commande déclenche un seul débit. Le solde ne peut pas devenir négatif.

Corps de la requête (JSON)

ParamètreTypeDescription
service_id requis string Identifiant au format provider_id obtenu via GET /api/v1/services (ex. "mtp_1234").
link requis string URL du profil, de la publication ou de la vidéo cible (ex. https://instagram.com/mon_compte).
quantity requis integer Quantité souhaitée, entre min et max du service. Ignorée si le service est de type package.
comments optionnel string Commentaires personnalisés. Supporté uniquement par les services de type custom comments (MTP, AfriqueBoost).

Réponse succès

200 OK
{
  "success": true,
  "order_id": "SBH-AUTO-1042",
  "service": "Instagram Followers [Real]",
  "quantity": 1000,
  "price": 5000,
  "currency": "XAF",
  "balance": 10000,
  "status": "pending"
}

Détail des champs de réponse

ChampTypeDescription
order_idstringIdentifiant unique de la commande (à utiliser pour le suivi).
servicestringNom du service commandé.
quantityintegerQuantité effectivement commandée.
priceintegerCoût total débité en XAF.
currencystringToujours "XAF".
balanceintegerNouveau solde après débit.
statusstringStatut initial : "pending".
 
curl -X POST https://socialboosthorizon.com/api/v1/order \
  -H "X-Api-Key: votre_cle_api" \
  -H "Content-Type: application/json" \
  -d '{
    "service_id": "mtp_1234",
    "link": "https://instagram.com/mon_compte",
    "quantity": 1000
  }'

    "X-Api-Key": "votre_cle_api",
    "Content-Type": "application/json"
}
data = {
    "service_id": "mtp_1234",
    "link": "https://instagram.com/mon_compte",
    "quantity": 1000
}

response = requests.post(url, headers=headers, json=data)
print(response.json())
$ch = curl_init();

$payload = json_encode([
    "service_id" => "mtp_1234",
    "link" => "https://instagram.com/mon_compte",
    "quantity" => 1000
]);

curl_setopt_array($ch, [
    CURLOPT_URL => "https://socialboosthorizon.com/api/v1/order",
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_POST => true,
    CURLOPT_POSTFIELDS => $payload,
    CURLOPT_HTTPHEADER => [
        "X-Api-Key: votre_cle_api",
        "Content-Type: application/json"
    ]
]);

$response = curl_exec($ch);
curl_close($ch);

$data = json_decode($response, true);
print_r($data);

    method: "POST",
    headers: {
        "X-Api-Key": "votre_cle_api",
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        service_id: "mtp_1234",
        link: "https://instagram.com/mon_compte",
        quantity: 1000

Statut d'une commande

GET /api/v1/order/:orderId

Récupère les informations d'une commande spécifique. Vous ne pouvez consulter que les commandes appartenant au compte associé à votre clé API.

Paramètres (URL)

ParamètreTypeDescription
orderId requis string Identifiant retourné lors de la création (ex. SBH-AUTO-1042).

Réponse

200 OK
{
  "success": true,
  "order": {
    "order_id": "SBH-AUTO-1042",
    "service": "Instagram Followers [Real]",
    "link": "https://instagram.com/mon_compte",
    "quantity": 1000,
    "price": 5000,
    "currency": "XAF",
    "status": "En cours",
    "created_at": "2026-02-14T10:30:00Z"
  }
}

Statuts possibles

  • En attente — commande transmise, en file chez le fournisseur.
  • En cours — traitement démarré.
  • Terminé — quantité livrée.
  • Partiel — livraison partielle (remboursement automatique du reste).
  • Annulé — commande annulée (remboursement automatique).

  -H "X-Api-Key: votre_cle_api"

order_id = "SBH-AUTO-1042"
url = f"https://socialboosthorizon.com/api/v1/order/{order_id}"
headers = {"X-Api-Key": "votre_cle_api"}

response = requests.get(url, headers=headers)
print(response.json())
$orderId = "SBH-AUTO-1042";
$ch = curl_init();

    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER => [
        "X-Api-Key: votre_cle_api"
    ]
]);

$response = curl_exec($ch);
curl_close($ch);

$data = json_decode($response, true);
print_r($data);

    headers: {
        "X-Api-Key": "votre_cle_api"

});

Codes d'erreur

L'API utilise les codes HTTP standards. En cas d'erreur, la réponse contient toujours un objet JSON avec success: false et un champ error contenant un message lisible.

Exemple d'erreur
{
  "success": false,
  "error": "Clé API manquante ou invalide."
}
CodeSignificationCause fréquente
200 Succès Requête traitée avec succès.
400 Requête invalide Paramètre manquant, quantité hors limites, service introuvable, solde insuffisant.
401 Non authentifié En-tête X-Api-Key absent, clé inconnue ou révoquée.
404 Ressource introuvable Commande inexistante ou n'appartenant pas à votre compte.
500 Erreur serveur Erreur interne ou fournisseur indisponible. Réessayez plus tard.

Bon réflexe

En cas de 500, n'effectuez pas de nouvelle tentative immédiate sans vérifier d'abord via GET /api/v1/order/:orderId que la commande initiale n'a pas été créée. Un système de retry avec vérification évite les doubles commandes.

Questions fréquentes

Comment recharger mon solde ?

Le solde se recharge depuis votre compte sur le site (Mobile Money ou carte bancaire). L'API publique ne gère pas encore la recharge.

La même clé peut-elle servir depuis plusieurs serveurs ?

Oui, mais chaque appel consomme du solde. Nous recommandons d'utiliser une seule clé par application.

Que se passe-t-il si une commande est annulée par le fournisseur ?

Le remboursement est automatique et crédité sur votre solde. Utilisez GET /api/v1/order/:orderId pour vérifier.

Existe-t-il une limite de débit (rate limit) ?

Un usage raisonnable est attendu. Toute détection d'abus peut entraîner une suspension temporaire de la clé. Évitez les boucles sans pause.

Puis-je utiliser cette API depuis un navigateur ?

Non, ce n'est pas recommandé. Une clé API exposée dans du JavaScript côté client peut être volée en quelques secondes. Utilisez toujours un serveur intermédiaire.

Le service a retourné « Service introuvable », que faire ?

Le catalogue évolue côté fournisseurs. Un identifiant valide aujourd'hui peut être retiré demain. Dans ce cas, refaites un appel à GET /api/v1/services et sélectionnez un service de remplacement.
